# hilla-tailwind

Full-stack media sync rule manager built with Kotlin, Vaadin Hilla, React, and Tailwind v4.

**Stack:** Spring Boot 4 · Kotlin · Vaadin Hilla 25 · React 19 · TypeScript · Tailwind v4 · PostgreSQL · Flyway

---

## Prerequisites

- JDK 21
- Node.js 20+
- Docker or Podman (for PostgreSQL)

---

## Setup

### 1. Start the database

```sh
docker compose up -d
```

This starts a PostgreSQL 17 container at `localhost:5432` with user/password/db all set to `postgres`. Data is persisted in a named volume (`postgres_data`).

To stop it:

```sh
docker compose down
```

To wipe data and start fresh:

```sh
docker compose down -v
```

### 2. Run the app

```sh
./gradlew bootRun
```

On first run, Gradle downloads dependencies, Flyway runs the database migration, and Hilla generates TypeScript endpoints from the Kotlin services. The browser opens automatically at `http://localhost:8080`.

---

## Development

Hilla's dev mode wires up Vite HMR for the React frontend while `bootRun` keeps the Spring backend running. Frontend changes (`.tsx`, `.css`) are reflected in the browser instantly; backend changes require a restart.

### Regenerating TypeScript endpoints

Endpoints are auto-generated into `src/main/frontend/generated/` whenever `bootRun` starts. If you add or change a `@BrowserCallable` Kotlin service, restart `bootRun` to pick up the new types.

## Testing

### Frontend (Vitest)

```sh
npm test              # single run
npm run test:watch    # watch mode
```

Tests use [Vitest](https://vitest.dev) + [React Testing Library](https://testing-library.com/docs/react-testing-library/intro). Hilla form hooks and generated service endpoints are mocked — no backend needed.

### Backend (JUnit 5)

Requires the database to be running.

```sh
./gradlew test
```

There are two test layers:

- **Unit tests** (`RuleServiceUnitTest`) — Mockito mocks, no database.
- **Integration tests** (`RuleEditorIntegrationTest`) — full Spring context against a real PostgreSQL instance (uses `ddl-auto: create-drop`, Flyway disabled). Each test rolls back via `@Transactional`.

The integration tests use `src/test/resources/application-test.yml`, activated via `@ActiveProfiles("test")`.

## Database

Connection details (default):

| Setting  | Value                                  |
|----------|----------------------------------------|
| URL      | `jdbc:postgresql://localhost:5432/postgres` |
| Username | `postgres`                             |
| Password | `postgres`                             |

Migrations live in `src/main/resources/db/migration/` and are applied by Flyway on startup.

To inspect the database directly:

```sh
psql -h localhost -U postgres -d postgres
```

```
src/
  main/
    kotlin/com/example/
      DemoApplication.kt          # Spring Boot entry point
      models/MediaRule.kt         # JPA entity
      repositories/               # Spring Data JPA repositories
      services/                   # @BrowserCallable Hilla services
    frontend/
      views/                      # File-based React routes
        @index.tsx                # → /
        rules.tsx                 # → /rules
      generated/                  # Auto-generated by Hilla (do not edit)
    resources/
      db/migration/               # Flyway SQL migrations
      application.yml
  test/
    kotlin/com/example/
      RuleServiceUnitTest.kt      # Mockito unit tests
      RuleEditorIntegrationTest.kt
    resources/application-test.yml
```

## Key gotchas

- `vaadin { javaSourceFolder = file("src/main/kotlin") }` in `build.gradle.kts` is required for Hilla's TypeScript generator to find Kotlin sources (it defaults to `src/main/java`).
- `@SpringBootApplication` must be in the root package (`com.example`) to scan sibling packages like `com.example.services`.
- Tailwind text color utilities on `h1`–`h6` elements need the `!` important modifier (e.g. `!text-slate-100`) because Vaadin's `aura.css` sets `color` on headings as an unlayered stylesheet, which beats Tailwind's `@layer utilities` regardless of specificity.
